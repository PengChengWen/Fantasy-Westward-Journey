# UI设计与生成规范

版本：0.2 · 日期：2026-10-19 · 适用项目：《照夜山海》。

本规范用于 UI 设计、素材生成与 Godot 实现。技术依据见 [技术选型方案](技术选型方案.md)，玩法依据见 [玩法设计总案](玩法设计总案.md)。

后续设计、生成、实现和修改本项目 UI 时，均使用以下规范。用户已经确定：采用类似《梦幻西游》电脑版的 Q 版国风回合制 RPG 气质。以下配色和尺寸是本项目的初始设计值，并非原作参数。

## 1. 整体风格

- 关键词：Q 版、国风神怪、温暖明快、圆润厚实、手绘质感、轻量立体、清晰易读。
- 视觉方向：米色纸绢、温润木框、青蓝点缀、哑金描边，搭配简化云纹、绳结、灯笼、玉饰和卷轴元素。
- 参考经典国风回合制游戏的亲和感、材质感与图标辨识度；面板结构、装饰纹样、按钮轮廓、角色形象和图标具体造型采用本项目原创设计。
- 以游戏中的真实用途组织内容，突出角色、宠物、装备、地图和战斗；不要把游戏界面做成网站后台、统计大屏或通用卡片仪表盘。
- 避免黑金写实仙侠、赛博霓虹、玻璃拟态、大片半透明毛玻璃、冷淡极简 SaaS 风格和写实金属机甲质感。
- Q 版主要体现在轮廓、比例、图标与装饰；正文和数值必须规整，不能为了可爱而难读。

## 2. 配色与语义

统一使用具名颜色令牌，不在各界面分别随意选色。以下为初始 sRGB 色值：

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| surface_canvas | `#F5E7C6` | 纸绢基底、小面积过渡 |
| surface_panel | `#FFF5DA` | 面板内容区、文本阅读背景 |
| frame_wood | `#68482F` | 木框与深色结构边缘 |
| frame_gold | `#C49A4A` | 哑金细边、重点装饰 |
| text_primary | `#38291E` | 正文、属性、常规数值 |
| text_secondary | `#715A40` | 次级说明、单位、辅助信息 |
| action_primary | `#2F6F77` | 主要操作、选中状态 |
| text_on_primary | `#FFF8E5` | 深色主按钮上的文字 |
| action_secondary | `#E8CEA0` | 次按钮、普通页签底色 |
| accent_warm | `#E0B65B` | 焦点装饰、稀有反馈的小面积强调 |
| status_health | `#B63D40` | 气血、损失气血 |
| status_mana | `#397AA5` | 真气 |
| status_positive | `#2F7048` | 恢复、可完成、正向变化 |

- 米色、木色为基底，青蓝强调操作，金色用于结构和重要反馈；避免整个窗口都用饱和金色或红色。
- 普通文字优先使用深色字配浅色底；金色不作为小号正文颜色。主要文字对比度目标至少 4.5:1，大字与非文本交互边界目标至少 3:1，实际输出后检查。
- 稀有度同时使用文字、边框形状或标记表达，不能只靠颜色区分。气血和真气也同时显示数值或缩写标签。
- 深色木框上的文字使用浅色字，不把 text_secondary 直接用于深色底。

## 3. 面板与材质

- 面板采用圆润木框或轻量卷轴边饰，内层为干净纸绢；纸张纹理保持低对比，不干扰文字。
- 装饰集中在标题栏、四角和分隔处，正文区域保持平整。每个大窗口通常只使用一种主要装饰主题。
- 适度内高光和柔和外投影，表现厚度；避免多层厚重浮雕、刺眼高光和过宽金属描边。
- 通用窗口至少复用标题栏、关闭按钮、内容区、页签和底部操作栏，不能为每个玩法重新设计一套视觉语言。
- 背景框、标题饰件、按钮底图采用可复用资源；适合拉伸的面板和按钮使用九宫格切片，装饰角和图案不得被直接拉变形。
- 玩法窗口遮罩只需让场景退后，不把整个游戏背景变成纯黑。弹层层级、点击阻挡与退出行为保持统一。

## 4. 按钮、页签与输入控件

- 主按钮使用青蓝底、浅色字和克制的金边；次按钮使用暖米色底、深棕字；危险操作使用明确文字及红色提示。
- 按钮轮廓圆润，带轻微厚度和按压反馈；保持完整可点击区域，装饰不得缩小命中范围。
- 所有交互控件包含正常、悬停、按下、选中、禁用和键盘焦点状态；只对适用的控件显示选中状态。
- 禁用状态要让文字仍可辨认，并可通过悬停、焦点或说明区得知原因，例如真气不足、正在休息、未变身。
- 页签选中时同时改变底色和标记，避免只能靠微小色差判断。
- 表格、列表与背包以行列关系承载信息，不把每条属性包进独立装饰卡片。
- 滚动条、数量步进、复选框与下拉菜单使用同一木色／青蓝体系，交互反馈一致。

## 5. 图标、角色头像与装饰

- 图标为手绘 Q 版插画：轮廓饱满、主题突出、柔和体积光，描边与内部细节层级清楚。
- 物品尽量用一个主体和少量陪衬表示，例如药瓶、符纸、剑、宝图、兽卵；不能塞入复杂场景导致缩小时无法识别。
- 同类图标统一光源、视角、描边和底托，选中框、品质框与物品图像分层。
- 头像强调较大的头部、清楚的表情和鲜明发饰／轮廓，预留边缘空间，避免裁切脸部和重要特征。
- 不使用 emoji、随机网络图标或风格不一致的图标库替代最终游戏图标；原型占位图应明确标记并集中替换。
- 功能小图标与技能、物品插画分规格制作；要在实际显示尺寸检查，不以放大图的精细程度代替可读性。

## 6. 字体、排版与适配

- 标题可使用有商用授权的圆润书写体或国风展示字体；正文、数值与提示使用清晰的中文黑体类字体。
- 禁止将大段正文、装备属性、按钮文字烘焙进图片；所有可变文本由 Godot 文本控件渲染。
- 字体随包记录授权、来源与缺字回退方案，验证中文标点、生僻字、数字、百分号和英文缩写。
- 以 1920×1080 为主要设计画布，同时验证 1280×720、超宽窗口与 UI 缩放。不要固定坐标后简单缩小整张截图。
- 1080p 初始字号参考：窗口标题 32、主要按钮与页签 24、正文 24、次级说明 21、关键战斗数字 28—36；可按实际字体调整。
- 720p 实际显示时，重要操作与正文目标不低于 16 像素，次级说明不低于 14 像素；必要时调整布局和 UI 缩放，不能继续压缩文字。
- 间距以 8 个设计像素为基准，采用 8／16／24／32 的层级。常用按钮在 1080p 下高度参考 48—56，缩放后保持足够的命中区域。
- 长文本换行，过长名称提供完整提示；数值不被省略成无法判断的缩写。文字扩展后不能压住关闭按钮、消耗材料或主要操作。

## 7. 主要界面布局

| 界面 | 信息与操作要求 |
| --- | --- |
| 探索主界面 | 角色与队伍状态、区域信息、小地图、任务追踪和常用功能入口分区；让地图仍是主体，不加入与单机无关的排行榜、充值入口或滚动广告 |
| 战斗界面 | 中间保留战场，显示五名角色与各自一只在场灵兽，我方最多十个单位；通过位置、主人名称或配对标记表达归属，分别显示角色与宠物的指令、状态和行动顺序 |
| 人物／门派 | 人物展示、装备位、核心属性、门派技能清楚分组；成长收益可比较，休息与血线条件写清楚 |
| 背包／装备 | 物品网格配详情区，显示数量、品质、用途、穿戴比较；材料、装备、任务物品可分类 |
| 宠物／炼妖 | 宠物外形与核心成长信息突出；亲本、材料、候选继承、锁定项和结果范围分区，不伪装成抽卡付费界面 |
| 打造 | 配方、材料、工艺、预览和费用同屏可核对；区分确定结果与随机范围，成功后突出成品并支持查看详情 |
| 帮派 | 以院落和建筑呈现归属感，成员、岗位、生产与委托可直达；建筑装饰不能遮住岗位占用和资源需求 |
| 宝图／世界地图 | 使用手绘纸图与可辨识地标；区分道路、船路、特殊入口与尚未解锁条件，传送与普通通行不能混淆 |

战斗指令统一为攻击、技能、防御、保护、道具、召回／召唤、撤退；技能菜单显示消耗与限制。睡眠、封物理、封法术、双封、休息、变身与持续恢复必须各有图标和可读说明。

角色和宠物的下令入口明确区分，支持逐组查看主人与宠物，也允许分别调整指令；自动策略不能掩盖尚未确认的单位。换宠界面显示当前主人、旧宠、新宠与“消耗主人本回合行动，新宠下回合行动”，不允许选择已被其他角色携带的宠物。主人倒地时仍须让玩家能操作其存活宠物。

战场布局至少检查双方各十个单位的样例，在 720p 下仍能辨识目标、归属与关键状态；不通过缩小全部字体挤下新增宠物。群体目标预览按技能上限标记，不能把五角色五宠误画为所有群体技能全队生效。

预计行动顺序、首领意图与目标预览，只展示规则允许玩家知道的信息；不得为了界面效果泄露 AI 隐藏指令或把概率显示为保证成功。

## 8. 动效与交互反馈

- 悬停和按钮反馈参考 100—180 毫秒，窗口出现与切页参考 180—240 毫秒；动画不延迟必要操作。
- 普通交互采用轻微亮度、位移与按压变化；避免大幅弹跳、持续抖动与所有按钮循环发光。
- 打造和炼妖可有短促的结果揭晓，支持加速或跳过；反馈长度不影响实际随机结果与扣除材料。
- 战斗数值、治疗、封印失败、资源不足和休息分别给出明确反馈，不只播放特效而不说明结果。
- 键盘焦点可见，菜单提供取消和返回；不能仅悬停才能读取关键条件。减少动效选项应关闭装饰循环、闪光与非必要镜头震动。

## 9. 生成素材与工程交付

每次生成前先明确：目标界面、用途、尺寸、风格令牌、组件状态、是否透明、切片方式与可变文字范围。

- 先做代表性样板：一个通用窗口、主／次按钮、一组物品图标和战斗指令区。检查统一性后再扩展背包、打造、炼妖等界面。
- 完整 UI 效果图用于确认构图与风格；实际实现拆分为面板、边框、饰件、按钮、图标与文本，不能把一张整屏图片当成交互界面。
- PNG 为透明 UI 资源的默认交付格式；需要透明背景时实际提供 alpha，不能把棋盘格或白色背景画进文件。
- 标注资源像素尺寸、显示尺寸、九宫格边距、安全内容区与对齐基线。切片边界不穿过不可拉伸的角饰，图集预留透明间隔以减少采样串色。
- 文本、计数、价格、属性、概率与快捷键由引擎绘制；生成图片中不要夹带英文占位字、乱码或假文字。
- 相同组件的多个状态保持画布、内容锚点和主体尺寸一致，避免切换时跳动。
- 文档使用中文文件名；工程素材路径采用稳定 ASCII 名称，例如 ui/panels/window_base.png、ui/buttons/primary_normal.png；不以中文显示名作为资源唯一 ID。
- 在技术方案所述工程建立后，使用 Control、Container、Theme、StyleBoxTexture 或 NinePatchRect 实现复用，并集中管理颜色、字体与组件尺寸。
- 原型占位素材与可发行素材分开标记，记录生成版本或素材来源；不直接提取参考游戏的面板、图标、字体或音效。

## 10. 可复用生成提示词

通用 UI 效果稿提示词，按实际功能替换方括号内容：

> 为原创国风神怪单机回合制 RPG《照夜山海》设计［界面名称］。采用经典 Q 版国风回合制游戏的温暖、圆润、亲和视觉气质，轻量手绘立体感，米色纸绢内容区、温润木框、青蓝主按钮、哑金细边，以少量原创云纹、灯笼或绳结装饰。画面层级清楚，主体为［角色／宠物／物品／地图／战场］，重点突出［本界面核心操作］，包含［必要信息区域］，预留真实中文文本区域。面向 PC 横屏，主要设计尺寸 1920×1080，同时考虑 1280×720 的排版。具体轮廓、图标、纹样与界面构图原创；避免现代后台卡片、写实黑金、霓虹、毛玻璃、过度装饰和细小文字。效果图如需示意文字，应作为独立排版参考，不将文字当作最终素材的一部分。

独立组件提示词：

> 为同一套 Q 版国风 RPG UI 制作［组件名称］，用途为［具体用途］，画布［宽×高］，保持米色纸绢、木色框、青蓝与哑金点缀的统一风格，主体轮廓圆润清晰，柔和阴影，预留［安全内容区］。［需要透明时：背景完全透明，输出带 alpha 的 PNG］。不包含文字、数字、品牌标志或水印。［需要多个状态时：分别提供正常、悬停、按下、选中、禁用，画布和锚点一致］。［需要九宫格时：四角保持完整，中间和边缘适合独立拉伸］。

提示词用于约束设计目标，不能代替对生成结果的实际检查；如果输出不满足透明、切片或尺寸要求，需要修正后再接入。

## 11. 验收清单

- [ ] 整体是温暖明快的 Q 版国风游戏 UI，面板、图标与角色画风一致。
- [ ] 采用统一配色、字体、边距、光源与组件状态，没有混入后台仪表盘风格。
- [ ] 正文、数值、消耗和状态在 1080p 与 720p 实际尺寸下可读，无重叠、裁切或缺字。
- [ ] 主要操作清楚，正常、禁用、选中、悬停与键盘焦点均可辨识，禁用原因可查询。
- [ ] 战斗界面符合五名角色各带一只宠物、我方最多十个单位的编成；归属、独立指令、换宠提示与七门派状态清楚可辨。
- [ ] 生成的概率、奖励、可行动状态与规则一致，没有为画面效果编造数据。
- [ ] 文本与美术分层，透明素材、九宫格、对齐和图集边缘经实际验证。
- [ ] 常用窗口能关闭、返回、缩放，重要操作不被装饰或小地图遮挡。
- [ ] 动画可跳过或减少，UI 反馈不影响战斗和养成结算。
- [ ] 不含参考游戏直接提取的素材、标志、独特角色或原界面追摹。
