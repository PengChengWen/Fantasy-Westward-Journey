# 开发环境与工程检查

版本：0.1 · 2026-10-19。

## 1. 工具链

- Windows x64 开发环境，PowerShell 7 用于现有检查脚本。
- .NET 10 SDK。global.json 的最低基线为 10.0.100，允许向前选择已安装的 10.0 正式 SDK feature band，不选预览版；它不是精确补丁锁。
- 当前项目目标框架为 net8.0，与查询到的 GodotSharp 4.7.2 包目标保持一致。SDK 版本与目标框架不是同一个概念；首次实际构建后仍需核对 Godot 导出包和运行时支持策略。
- 运行核心测试和工具时需要 .NET 8 运行时，CI 同时配置 10.0 与 8.0 SDK。客户端由匹配版本的 Godot .NET 环境加载。
- Godot 4.7.2 .NET 编辑器；后续导出必须安装同版本的 .NET 导出模板。

本机首次检查结果：仅发现 .NET 8.0.7 和 10.0.8 运行时，没有 SDK，PATH 中没有 Godot。因此本次不声称已经通过 C# 编译、单元测试或 Godot 启动验证。不要把旧运行时安装记录当作推荐部署版本。

## 2. 核心命令

从仓库根目录执行：

```powershell
pwsh -File ./scripts/检查工程结构.ps1
pwsh -File ./scripts/生成门派技能升级表.ps1 -Check
dotnet --info
dotnet restore Game.Core.slnx
dotnet build Game.Core.slnx --no-restore
dotnet test tests/Game.Domain.Tests/Game.Domain.Tests.csproj --no-build
dotnet run --project tools/ContentPipeline/ContentPipeline.csproj -- game/data/bootstrap.json
```

ContentPipeline 成功时输出配置哈希、门派数量和最大友方单位数；校验失败应返回非零退出码。

## 3. 客户端命令

```powershell
dotnet restore game/Game.Client.csproj
dotnet build game/Game.Client.csproj --no-restore
```

然后使用 Godot .NET 编辑器导入 game/project.godot 并运行主场景。当前只输出日志，不显示游戏 UI，不能据此判断战斗或界面已经完成。

安装并将正确编辑器加入 PATH 后，可额外执行以下导入检查。无图形模式检查不是可视化或导出验收：

```powershell
godot --headless --path game --editor --quit
```

## 4. 依赖与锁文件

Godot.NET.Sdk 固定为 4.7.2；测试依赖显式指定版本。Directory.Build.props 已启用生成 packages.lock.json。由于本机没有 SDK，本次未伪造这些锁文件。

第一次成功 restore 后，检查并提交生成的 packages.lock.json，再将 CI 的 restore 改为 --locked-mode。当前 CI 采用普通 restore，因此依赖传递解析尚未完全锁定。

SDK 具体版本应在首次构建记录中保存；团队确定统一补丁后，可将 global.json 改为更严格的 rollForward 策略。不要为了追版本，在内容开发中途随意升级引擎、导出模板与 SDK。

## 5. 测试范围

当前规则测试源码覆盖五角色五宠、重复角色、重复宠物、无宠物、六人超限、空编队和无效宠物 ID。

后续增加战斗测试时覆盖完整行动时序，而不是仅测试常量；存档迁移和奖励事务实际实现后，再为 Game.Application.Tests 建立项目。预留目录不表示测试已存在。

## 6. 日常提交前

1. 执行结构检查与门派费用表一致性检查；安装 SDK 后同时执行构建和规则测试。主动调整费用曲线时，先更新曲线版本与审核总额，再运行 scripts/生成门派技能升级表.ps1 生成完整费用表。
2. 若修改初始内容，执行 ContentPipeline。
3. 若修改引擎场景或脚本，进行 Godot 实际运行检查。
4. 用 git diff --check 检查空白错误，检查待提交文件不含缓存、构建包或凭据。

当前 validate.yml 仅声明 CI 流程，首次远程执行结果需要单独查看，不因存在文件就标记验证成功。
